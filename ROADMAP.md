# ROADMAP — Moonveil: Eclipse

Версия: 0.1
Статус: канонический план подготовки первого вертикального среза
Базовый манифест: GAME_MANIFEST.md

## Правило статусов

- PLANNED — этап ещё не начат.
- IN PROGRESS — есть работа, но критерии закрытия не выполнены.
- REVIEW — результат создан и проверяется.
- DONE — все deliverables существуют, подключены к нужному месту и пройдены критерии закрытия.
- BLOCKED — есть конкретная причина, зафиксированная в журнале этапа.

План не разрешает объявлять этап DONE по намерению, списку файлов или красивому превью. Для DONE нужны фактический результат, проверка и запись evidence.

## Порядок работы

Этапы выполняются последовательно. Следующий этап не начинается, пока предыдущий не закрыт или пользователь явно не изменил порядок. Если во время этапа обнаруживается дополнительная идея, она попадает в backlog и не расширяет текущий этап.

Текущий активный этап после подготовки документации: **1. Мокап меню**.

## Этапы 1–10: визуальная основа

### 1. Создание меню

Status: PLANNED.

Deliverables:

- главный экран;
- логотип и рабочее название;
- кнопки Start, Heroes, Arsenal, Artifacts, Settings;
- экран выбора героини;
- состояния кнопок: normal, pressed, disabled, locked;
- экран загрузки и экран результата;
- мобильный макет 390×844;
- описание переходов между экранами.

DONE только когда выбранный макет утверждён, все обязательные состояния показаны, текст читается на телефоне, а навигационный маршрут не имеет тупиков.

### 2. Создание мокапа арены

Status: PLANNED.

Deliverables:

- карта Затопленного сада Лунного лотоса;
- границы игровой области и камера;
- стартовая точка героини;
- зоны появления врагов;
- декоративные слои: вода, мосты, фонари, лотосы, туман, луна;
- места для HUD, босса и подсказок;
- визуальный контраст пола, врагов, снарядов и опасных зон.

DONE только когда арена читается без интерфейса, не мешает навигации и имеет понятную композицию для вертикального экрана.

### 3. Создание мокапов двух героинь

Status: PLANNED.

Для каждой героини нужны: портрет, full-body референс, боевой спрайт, цветовой код, силуэт, idle, движение, базовая атака, активная способность и экран выбора.

Героини: Линь Юэ — Нефритовая ведьма; Соён Хан — Алый клинок.

DONE только когда героини различаются визуально и механически, а боевой масштаб остаётся читаемым при массовой волне.

### 4. Создание мокапов противников

Status: PLANNED.

Нужно создать визуальные карточки десяти противников, указать размер, цветовой маркер, тип движения, дальность атаки, уязвимость и фазу появления.

DONE только когда каждый враг узнаётся по силуэту и его поведение можно понять без длинного текста.

### 5. Создание мокапов боссов

Status: PLANNED.

Нужно создать четыре концепта боссов, портреты, боевые силуэты, арену появления, фазы, телеграфы атак, шкалу здоровья и награду.

Боссы: Хуа Линь, Миён, Сэйка и Императрица Чёрной Луны.

DONE только когда у каждого босса есть минимум две читаемые механики, визуальные предупреждения и отдельный визуальный образ.

### 6. Создание мокапов оружия

Status: PLANNED.

Нужно создать иконки, карточки, боевые эффекты и эволюции десяти видов оружия. Для каждого оружия фиксируются цвет, форма снаряда, зона поражения и место в UI.

DONE только когда оружие можно отличить на поле, в слоте HUD и на карточке улучшения.

### 7. Создание мокапов пассивных навыков

Status: PLANNED.

Нужно создать десять иконок пассивок, карточки уровней, короткие описания, числовые модификаторы и связанные синергии.

DONE только когда иконка, название и эффект однозначно соответствуют друг другу.

### 8. Создание мокапов артефактов

Status: PLANNED.

Нужно создать минимум восемь артефактов, их редкость, иконки, карточки, эффекты внутри забега и экран постоянного Кодекса реликвий.

DONE только когда артефакты визуально отличаются от оружия и пассивок и имеют понятный источник получения.

### 9. Создание мокапов опыта и градаций

Status: PLANNED.

Базовая градация опыта:

| Предмет | Цвет/размер | Опыт | Назначение |
|---|---|---:|---|
| Малая искра | белая, маленькая | 1 | обычный враг |
| Осколок | голубой | 5 | усиленный обычный враг |
| Кристалл | фиолетовый | 15 | редкий враг или серия убийств |
| Большой кристалл | золотой | 40 | элитный враг |
| Ядро элиты | красно-фиолетовое | 80 | сильный элитный враг |
| Ядро босса | багрово-золотое | 250 | победа над боссом |

Deliverables: мокапы предметов, анимация появления, магнитное притяжение, эффект подбора, числовая таблица и начальная кривая уровня.

Стартовая балансировочная цель: первый уровень примерно за 30–45 секунд, первое значимое решение по билду до 90 секунд, первая эволюция около 8–12 минуты при удачной сборке.

DONE только когда градации различимы на поле и подтверждены тестовым забегом.

### 10. Создание мокапов HUD

Status: PLANNED.

Нужно создать HUD вертикального забега:

- таймер;
- шкала опыта;
- уровень героини;
- здоровье и щит;
- активная способность и её cooldown;
- шесть слотов оружия;
- шесть слотов пассивок;
- три слота артефактов;
- шкала босса;
- кнопка паузы;
- уведомления об эволюции и опасной атаке.

DONE только когда HUD не закрывает поле, не конфликтует с вырезами экрана и остаётся читаемым при максимальном количестве эффектов.

## Этапы 11–19: привязка и игровые интерфейсы

### 11. Манифест анимаций оружия и привязки

Status: PLANNED.

Для каждого оружия создаётся manifest с полями: weapon_id, animation_id, attack_type, hit_window, projectile_scene, vfx_id, sfx_id, haptic_pattern, cooldown, pool_key, evolution_id.

Нужно описать idle/charge/fire/travel/hit/expire/evolution и привязать каждую анимацию к конкретному оружию.

DONE только когда у каждого оружия есть полный путь от игровой команды до визуального, звукового и тактильного отклика.

### 12. Мокапы пассивок и привязка к каждой

Status: PLANNED.

Для каждой пассивки фиксируются passive_id, icon_id, max_rank, short_description, long_description, stat_modifiers, upgrade_values и список synergy_weapon_ids.

DONE только когда карточка, описание, числовой эффект и синергия используют один и тот же идентификатор.

### 13. План аудиосопровождения

Status: PLANNED.

Нужно описать:

- музыкальные слои 0–5, 5–10, 10–15 и 15–20 минут;
- отдельные темы четырёх боссов;
- звук попадания, смерти, подбора опыта, уровня, эволюции и открытия сундука;
- отдельные звуки для огня, льда, грома, зеркал, лотоса и затмения;
- приоритеты микширования при большом количестве событий;
- громкость музыки, эффектов и вибрации;
- форматы, имена файлов, лицензии и fallback при отсутствии ресурса.

DONE только когда у каждой ключевой игровой ситуации есть аудиосигнал и план не требует нелицензионных ассетов.

### 14. Мокапы анимаций смерти противников

Status: PLANNED.

Для десяти противников создаются storyboard или sprite/VFX-мокап: попадание, stagger, смерть, исчезновение, drop опыта и редкий элитный вариант.

DONE только когда смерть читается за долю секунды, не перекрывает следующий объект и не создаёт визуальный шум.

### 15. Мокапы анимаций смерти боссов

Status: PLANNED.

Для четырёх боссов нужны: потеря брони, переход фазы, финальное поражение, разрушение печатей, эффект награды и переход к экрану результата.

DONE только когда смерть босса ощущается наградой, но не задерживает игрока чрезмерно и корректно завершается при паузе/сворачивании.

### 16. Интерфейс предложения и выбора улучшений

Status: PLANNED.

Нужно создать экран уровня с тремя карточками, типами New/Upgrade/Evolution, иконкой, названием, описанием, текущим и новым значением, редкостью, состояниями выбора и запретом выбора при паузе.

DONE только когда игрок за несколько секунд понимает, что именно изменится после нажатия.

### 17. Интерфейс артефактов и описания

Status: PLANNED.

Нужно создать экран выбора артефакта в забеге, экран Кодекса реликвий, уровень I–V, источник получения, стоимость улучшения, активный эффект и историю разблокировки.

DONE только когда временный эффект забега и постоянное улучшение не смешиваются в одном описании.

### 18. Логика синергий оружия и пассивок

Status: PLANNED.

Первая версия использует десять прямых пар. Логика должна проверять: weapon_level = max, passive_rank = max, weapon не эволюционирован, сундук доступен, пара совпадает по synergy_id.

Нужно определить приоритеты, повторное открытие, отсутствие нужной пассивки, замену карты, сохранение эволюции и защиту от двойного срабатывания.

DONE только когда все десять синергий проходят позитивные и негативные тесты, включая невозможность эволюции без обоих компонентов.

### 19. Информационный интерфейс синергий

Status: PLANNED.

Нужно создать экран и подсказки: что уже собрано, чего не хватает, какое оружие с чем синергирует, какой уровень нужен, какой будет результат и где получить недостающую пассивку.

DONE только когда игрок может узнать путь к эволюции без внешней таблицы или угадывания.

## Этап 20. Дополнительные предложения

Status: DOCUMENTED; внедрение планируется после оценки влияния на M1.

Рекомендуется включить в backlog:

1. Короткое onboarding-обучение в первые 60 секунд: движение, подбор опыта, карточка и пауза.
2. Настройки доступности: леворукое управление, размер текста, отключение вспышек, цветовые маркеры без зависимости от одного цвета, сила вибрации.
3. Два режима прицеливания: автоматический по умолчанию и ручное направление для более выраженного Crimsonland-ощущения.
4. Безопасный режим производительности: качество VFX, лимит частиц и плотность вторичных эффектов.
5. Детерминированный seed забега и диагностический экран для воспроизведения проблем баланса.
6. Журнал происхождения ассетов: автор, лицензия, источник, дата и разрешение на коммерческое использование.
7. Версионирование сохранений и безопасная миграция после обновления.
8. Защита от плохого прогресса: гарантированная полезная карта после нескольких неудачных предложений, без обязательной платной гачи.
9. Data-driven контент: числовые параметры врагов, оружия и пассивок меняются в данных, а не через переписывание логики.
10. Экран статистики забега: урон по типам, время жизни оружия, полученный опыт, причина смерти и использованные синергии.

Эти предложения улучшают качество, доступность, баланс и поддерживаемость, но не должны блокировать M1 без отдельного решения.

## Этап 23. Roadmap и инструкции закрытия

Status: DONE — ROADMAP.md, AGENT_CONTEXT.md и индекс артефактов опубликованы.

Закрытие каждого этапа требует:

1. созданных deliverables;
2. ссылки или пути на каждый deliverable;
3. проверки соответствия манифесту;
4. проверки отсутствия незакрытых заглушек в пределах этапа;
5. evidence: preview, тест, скриншот, воспроизводимый сценарий или другой подходящий результат;
6. записи статуса DONE в этом roadmap;
7. краткого handoff для следующего этапа.

## Шаблон записи закрытого этапа

Stage: номер и название
Status: DONE
Deliverables: список путей
Verification: что проверено и каким способом
Evidence: ссылки на preview, тест или APK
Known limitations: только то, что вынесено за пределы этапа
Next stage: следующий номер

Финальный проект не считается готовым, пока пользовательский сценарий не проходит целиком:

выбор героини → запуск арены → движение → убийства → опыт → улучшения → синергия → босс → артефакт → финальный босс → результат → сохранение → повторный запуск.

Все статусы после публикации этого плана обновляются только по фактическим результатам, а не по намерению или описанию будущей работы.
