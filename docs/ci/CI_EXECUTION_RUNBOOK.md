# CI Execution Runbook

## Decision

- **Canonical source:** GitHub repository `xxiamadelxx-blip/mac`, branch `main`.
- **Runtime executor:** GitHub Actions workflow `R1 Runtime Verification`.
- **Godot environment:** `barichello/godot-ci:4.7.2`.
- **GitLab role:** downstream mirror only. `.github/workflows/mirror-to-gitlab.yml` pushes the exact GitHub branch and tag refs to `gitlab.com/xxiamadelxx-blip/mac`.
- **CircleCI role:** legacy and not an acceptance source until its external project is reconnected. A stale `ci/circleci: godot-validate` check may remain `pending`; do not treat it as proof that runtime is blocked or verified.

This split is intentional: GitHub Actions is the executor that is currently reachable and has produced a real Godot job. GitLab is kept as a synchronized copy for repository access and continuity.

## Agent protocol

1. Work only in the files owned by the current agent.
2. Publish an atomic commit to `main` (or a reviewed branch that is merged to `main`).
3. Wait for **R1 Runtime Verification** to finish.
4. Accept the runtime slice only when the job conclusion is `success` and its log contains:
   - `R1_RUNTIME_TEST` with `"ok":true`;
   - `R1_RUNTIME_TRACE` with `"ok":true`;
   - no `SCRIPT ERROR`, `Parse Error`, or invalid-call failure in the runtime execution.
5. Confirm the **Mirror GitHub to GitLab** workflow finished successfully and that GitLab points to the same commit SHA.
6. Report the commit SHA, workflow run URL, job conclusion, and any residual warnings. Never manufacture a trace when the runner did not execute.

A local PC or local Godot installation is not required for this flow.
